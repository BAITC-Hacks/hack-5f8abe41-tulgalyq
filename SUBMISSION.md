# Tulgalyq — описание для жюри

**Исходный код:** [репозиторий команды](https://github.com/BAITC-Hacks/hack-5f8abe41-tulgalyq) · [ветка `Moldiyar` для оценки участника](https://github.com/BAITC-Hacks/hack-5f8abe41-tulgalyq/tree/Moldiyar) · [основная ветка `main`](https://github.com/BAITC-Hacks/hack-5f8abe41-tulgalyq/tree/main). Репозиторий может быть приватным: для клонирования нужен доступ GitHub. Архив не требуется.

**Комплект сдачи:** работающий MVP из исходного кода, [README с архитектурой, формулой, каталогом и тестами](README.md), [сценарий демонстрации до 5 минут](DEMO.md), [сверка с кейсом](CASE_CHECKLIST.md). В приватный репозиторий по решению команды временно включён `.env` для живого Gemini; локальная база `data/` в Git не входит. После оценки ключ нужно отозвать.

## Одним предложением

Tulgalyq превращает расплывчатый запрос бизнеса в проверяемую студенческую миссию: AI помогает уточнить описание, бизнес подтверждает факты, а открытый рейтинг показывает, насколько задача готова к работе.

## Проблема и решение

Команде трудно откликаться на задачу, когда неизвестны данные, ожидаемый результат или критерии успеха. Привычный рейтинг компании этого не решает. Мы оцениваем не компанию и не студентов, а **готовность одной конкретной задачи** по шкале 0–100 из кейса. Пустоты видны всем, но даже карточка с низким баллом остаётся в каталоге и принимает предложения.

Бизнес вводит идею свободным текстом. При настроенном API Gemini предлагает три уточняющих вопроса; без ключа работают локальные вопросы. Ни один режим не добавляет фактов в карточку. Бизнес дополняет поля и вручную подтверждает публикацию; до этого рейтинг остаётся предварительным. Команды видят подтверждённую версию, отправляют идею и план, а бизнес самостоятельно выбирает одну, несколько или ни одной команды. Прогресс команды получает баллы только после подтверждения этапа.

## Что отличает проект

1. **Рейтинг-навигатор, а не витрина популярности.** Отдельный экран показывает подтверждённые баллы по каждой задаче, расшифровку по полям и что уточнить для следующего уровня готовности.
2. **Паспорт миссии.** Из опубликованной карточки скачивается бриф с подтверждёнными сведениями, рейтингом и открытыми вопросами. Несогласованные правки не попадают в файл или каталог.
3. **Выбор по предложениям, не по популярности.** Идеи и планы команд показаны рядом; бизнес может выбрать несколько команд, отклонить предложения или не принять решения. В демо-данных для одной задачи есть три разных варианта.
4. **AI под контролем человека.** Модель задаёт вопросы, но не придумывает материалы, сроки и показатели, не публикует карточку и не выбирает исполнителя. Если API недоступен, интерфейс честно показывает локальный режим.

## Как показать за три минуты

Используйте [сценарий демо](DEMO.md): слабая задача в каталоге → повышение готовности после подтверждения → скачивание паспорта → предложение команды → ручной выбор → баллы за подтверждённый этап → живые AI-вопросы и мобильный интерфейс.

## Как запустить и проверить

На компьютере с Python 3.9+ (сторонние пакеты не нужны):

```sh
git clone --branch Moldiyar https://github.com/BAITC-Hacks/hack-5f8abe41-tulgalyq.git
cd hack-5f8abe41-tulgalyq
python3 app.py
```

Откройте `http://127.0.0.1:8000/`. Если проект уже скачан, начинайте с перехода в его папку. Свежая база пуста: в «Каталоге задач» нажмите «Добавить демо-данные», чтобы получить 5 карточек, 5 черновиков, 5 команд и 7 синтетических откликов. Для ручного ввода в «Конструкторе» нажмите «Попробовать на примере» → «Продолжить».

**Живой Gemini:** ключ уже есть в `.env` этого приватного репозитория, поэтому отдельный ключ для проверки не требуется. Проверка настройки: `http://127.0.0.1:8000/api/health` должен показать `"ai_provider": "gemini"`; затем создайте тестовый черновик и убедитесь, что вопросы действительно помечены Gemini. Если ключ будет отозван или API временно недоступен, основной сценарий продолжит работать с локальными вопросами.

Автотесты: `python3 -m unittest -q test_app.py`. Они используют временную SQLite-базу и не меняют данные сайта. Пошаговое демо и ожидаемые результаты — в [DEMO.md](DEMO.md) и [README.md](README.md).

Полная [сверка с требованиями кейса](CASE_CHECKLIST.md) отделяет реализованный MVP от ограничений: это демо без авторизации и публичного хостинга, не готовый сервис для реальных персональных данных.
