# Tulgalyq

Исходный код: [GitHub · BAITC-Hacks/hack-5f8abe41-tulgalyq](https://github.com/BAITC-Hacks/hack-5f8abe41-tulgalyq), ветка участника — [`Moldiyar`](https://github.com/BAITC-Hacks/hack-5f8abe41-tulgalyq/tree/Moldiyar).

Рабочий прототип платформы бизнес-задач для HackAlem AI. Бизнес вводит свободное описание, отвечает на уточняющие вопросы, редактирует и подтверждает карточку. После подтверждения она попадает в каталог, где команды могут предложить решения. Сайт адаптирован для компьютера и телефона.

**Идея:** сильным студентам нужна не «популярная компания», а задача, с которой реально можно начать работу. Tulgalyq показывает готовность *конкретной задачи*: AI помогает задать правильные вопросы, бизнес подтверждает факты, а рейтинг 0–100 объясняет, чего ещё не хватает. Неидеальная задача остаётся в открытом каталоге и может получить отклик.

Отличия: прозрачный путь к 100 баллам без автопубликации AI-текста; открытый выбор нескольких команд самим бизнесом; скачиваемый «паспорт миссии» с подтверждёнными сведениями и пробелами для обсуждения. [Описание для жюри](SUBMISSION.md) · [Демо за 3 минуты](DEMO.md) · [Сверка с кейсом](CASE_CHECKLIST.md).

## Запуск

Нужен Python 3.9 или новее. Внешние пакеты не требуются.

```bash
python3 app.py
```

Откройте <http://localhost:8000>. Данные сохраняются в `data/tulgalyq-demo.sqlite3`; эта папка не попадает в Git. Прежняя локальная база `data/mission100.sqlite3` сохранена и не удалена. Чтобы снова открыть её, запустите сервер с `MISSION100_DB_PATH=data/mission100.sqlite3`.

Для быстрого старта нажмите «Попробовать на примере» в конструкторе: текст и тема заполнятся без сохранения задачи. Затем «Продолжить» покажет уточняющие вопросы. Для короткого показа жюри используйте [сценарий демо](DEMO.md). [Сверка с пунктами кейса](CASE_CHECKLIST.md) показывает, где реализован каждый обязательный сценарий и что ещё требует живой проверки.

## Проверка сквозного сценария

1. В «Конструкторе» введите слабое описание задачи и ответьте на три уточняющих вопроса.
2. Заполните название и потребность, откройте карточку: справа видны предварительный рейтинг и баллы за каждое поле. Добавьте сведения, затем сохраните и подтвердите карточку. В отдельном разделе «Рейтинг задач» проверьте подтверждённый балл, разбивку и недостающие сведения.
3. В «Каталоге» найдите опубликованную задачу. По умолчанию карточки упорядочены по рейтингу; проверьте фильтры темы и четырёх уровней готовности. Даже подтверждённая задача с низким баллом принимает отклики.
4. Создайте команду с интересами, навыками и технологиями, отправьте идею, план, срок и ссылку на прототип.
5. В «Выборе команд» отфильтруйте задачу, сравните предложения рядом, выберите одну, несколько или ни одной команды. Для выбранной команды отправьте этап работы и подтвердите его: после этого в рейтинге прогресса команд появятся 10 баллов.

Для автоматической проверки запустите `python3 -m unittest -v test_app.py`; тесты используют временную базу и не меняют данные сайта.

## Что работает сейчас

- Создание черновика из свободного текста.
- Три уточняющих вопроса о недостающих данных. Перед сохранением ответов AI проверяет, что они осмысленны и относятся к вопросу; найденные проблемы показаны рядом с полем. Перед публикацией сервер повторно проверяет все непустые поля карточки.
- Редактируемая карточка с полями из кейса.
- Предварительный рейтинг по шкале 0–100 и подсказки о недостающих полях. Сервер не засчитывает очевидные заглушки, повторы символов/слов и контакт без способа связи; редактор объясняет причину.
- Ручное подтверждение карточки; только после него баллы считаются начисленными.
- После публикации конструктор очищается, а подтверждённая задача показывается в «Задачах бизнеса» с кнопкой перехода в каталог. Редактировать и повторно подтвердить её можно позже.
- Сохранение карточки между перезагрузками браузера. При правке опубликованной задачи последняя подтверждённая версия остаётся в каталоге и на странице откликов; новые поля становятся публичными только после повторного подтверждения.
- Демо-кабинет бизнеса со всеми черновиками и опубликованными карточками: можно продолжить уточнение, открыть редактор или перейти к задаче в каталоге. Пока нет авторизации, это общий список записей демо-базы, а не персональные «мои задачи».
- Подробная разбивка баллов по каждому полю: видно, какие баллы уже подтверждены, какие возможны после подтверждения и что ещё пусто.
- Отдельный раздел «Рейтинг задач» со всеми опубликованными задачами, фильтром по уровню готовности, расшифровкой начисления и списком недостающих полей; из него можно открыть карточку в редакторе или каталоге.
- Общий каталог только подтверждённых задач: по умолчанию задачи идут по убыванию рейтинга; доступны поиск, фильтры по теме и уровню готовности, а также сброс фильтров. Низкий рейтинг не блокирует отклики.
- Необязательный подбор до трёх задач по совпадению слов в интересах/навыках команды и описании миссии. Он объясняет совпадения и предлагает задачи от 40 баллов; остальные задачи по-прежнему видны в общем каталоге. Это локальное правило, не AI и не автоматический выбор исполнителя.
- Профили команд с интересами, навыками и технологиями; неограниченные предложения с идеей, планом, сроком и обязательной ссылкой на прототип.
- Экран ручного выбора: отклики показаны рядом для сравнения идей, планов, сроков и прототипов; есть фильтр по задаче и статусу, числа ожидающих/выбранных/отклонённых и переход из кабинета бизнеса к конкретной миссии.
- Ручное решение бизнеса: выбрать одну или несколько команд, отклонить или не принимать решения.
- Подтверждение выполненного этапа даёт команде 10 прогресс-баллов; повторно подтвердить тот же этап нельзя. Баллы видны в таблице прогресса команд.
- Кнопка демо-данных добавляет 5 синтетических карточек с разными рейтингами, 5 черновиков разной полноты, 5 команд и 7 предложений; по первой задаче можно сравнить три подхода. Для старой демо-базы повторное нажатие добавит только два недостающих альтернативных отклика, не дублируя остальное. Ссылки в демо-записях служат образцом формата, а не действующими прототипами. Уже созданные записи не переписываются обновлением приложения.
- После создания черновика AI автоматически предложит три уточняющих вопроса. При наличии `GEMINI_API_KEY` используется Gemini; если его нет, но есть `OPENAI_API_KEY`, используется OpenAI; иначе — локальные правила. Кнопка позволяет запросить вопросы повторно. AI не заполняет карточку и не начисляет баллы без ответа бизнеса.
- Из опубликованной задачи скачивается Markdown-«паспорт миссии»: исходный запрос, подтверждённые поля, рейтинг и вопросы к ещё неясным пунктам. Несогласованные правки редактора в экспорт не попадают.

## Формула рейтинга

Контекст — 10, потребность — 10, данные — 20, ожидаемый результат — 15, критерии успеха — 15, ограничения — 10, пользователи — 10, контакт — 5, формат взаимодействия — 5. Сумма — 100. Пустое поле, очевидная заглушка, повтор символов/слов и несколько расплывчатых ответов не дают баллов. Для критериев успеха нужен измеримый признак; для контакта — email, @ник, ссылка или телефон минимум из 7 цифр. Сервер возвращает причины в `quality_issues`; локальная проверка не доказывает смысл и достоверность текста. Изменение подтверждённой карточки требует нового подтверждения: предварительный балл виден в редакторе, а прежний подтверждённый балл и карточка сохраняются в каталоге до публикации правок. Ранее подтверждённые баллы локальной базы не пересчитываются задним числом.

Уровни из кейса: 0–39 — «черновик», требует уточнения; 40–69 — рабочая; 70–89 — готовая; 90–100 — приоритетная. «Черновик» здесь обозначает уровень готовности, а не статус публикации: подтверждённая бизнесом задача даже с 0 баллами видна в каталоге и принимает отклики. Для неполной карточки каталог показывает исходное описание бизнеса вместо отсутствующего или некорректного названия. Не подтверждённая человеком карточка остаётся в редакторе и не публикуется. После подтверждения дополнений рейтинг пересчитывается; при одинаковом рейтинге сохраняется порядок новых задач.

## Мобильный интерфейс

Это тот же сайт: на широком экране пять разделов расположены по центру шапки. На узком экране карточки перестраиваются в одну колонку, крупные кнопки подходят для касания, а разделы открываются боковым меню через кнопку ☰. Кнопка ☾ переключает светлую и тёмную темы; выбор сохраняется в этом браузере. В редакторе краткий рейтинг виден перед полями, а расшифровка раскрывается по нажатию. Подбор задач на телефоне тоже можно раскрыть при необходимости, не прокручивая его перед каталогом. Для просмотра на этом ноутбуке откройте `http://localhost:8000`. Адрес `localhost` на телефоне указывает на сам телефон, поэтому для проверки на другом устройстве понадобится отдельный доступ к серверу по локальной сети или хостинг.

Сейчас это **демо без авторизации и разграничения ролей**: не размещайте его публично с реальными данными, пока не будут добавлены роли бизнеса/команд и права на изменение своих записей.

## AI-вопросы и локальный режим

Скопируйте `.env.example` в локальный `.env`, вставьте секретный ключ после `GEMINI_API_KEY=` и перезапустите сервер. `.env` исключён из Git и не попадает к жюри вместе с репозиторием. Ранее отправленный в чат ключ нужно перевыпустить; его не следует использовать или сохранять в коде. Можно также задать `GEMINI_API_KEY` в окружении процесса сервера: эта переменная имеет приоритет над `.env`.

```sh
cp -n .env.example .env
# Заполните GEMINI_API_KEY в .env локально
python3 app.py
```

Открывайте `http://127.0.0.1:8000/`; если порт уже занят, остановите прежний сервер в его терминале сочетанием Ctrl+C и запустите новый. По умолчанию Gemini использует `gemini-3.5-flash-lite` (модель с бесплатным тарифом на момент подготовки прототипа); можно изменить её через `GEMINI_MODEL`. Если Gemini-ключа нет, но задан `OPENAI_API_KEY`, будет использован OpenAI Responses API с моделью `gpt-4o-mini` (можно изменить через `OPENAI_MODEL`). Ключ должен находиться **только на сервере**: это соответствует [рекомендациям Google](https://ai.google.dev/gemini-api/docs/api-key). При создании черновика или повторном нажатии кнопки исходное описание, сохранённые поля и уже набранные ответы отправляются выбранной модели. Набранные ответы не сохраняются в карточку автоматически. Без ключа кнопка честно называется «Локальные вопросы». Если API не ответил или вернул некорректный результат, сервер возвращает три локальных вопроса; введённые ответы остаются на месте. Интерфейс отдельно показывает отказ в доступе к API и достижение лимита, не раскрывая ключ.

Ссылка на страницу OpenAI Platform или промоакцию — не API-ключ. Если вместо ключа в `OPENAI_API_KEY` указана веб-ссылка, приложение не отправляет её в API, сообщает о неверной настройке и использует локальные вопросы. Создайте секретный ключ в [разделе API keys](https://platform.openai.com/api-keys) и введите его только в окружение процесса сервера; не вставляйте ключ в чат, браузерный JavaScript или Git.

Промпт просит ровно три разных вопроса на русском, каждый привязан к недостающему или расплывчатому полю, без выдумывания фактов и повторения известных сведений. Его точный текст хранится в `AI_INSTRUCTIONS` в `app.py`. Вход модели — JSON с `description` и `fields`; выход — JSON-объект с массивом `questions`, где каждый элемент содержит `field` (например, `users`) и `text` (например, «Кто будет пользоваться решением?»). Для ответа Gemini используется [структурированный JSON](https://ai.google.dev/gemini-api/docs/structured-output); для OpenAI — Structured Outputs. Сервер проверяет завершённость ответа, количество, разные поля, разные формулировки и длину вопросов; некорректный ответ не меняет карточку и включает локальный резервный режим. API браузера `POST /api/tasks/{id}/ai-questions` принимает необязательный JSON `{"answers":{"need":"..."}}` и отвечает `{"questions":[{"field":"data","text":"..."}],"source":"gemini"}` либо `"source":"openai"` или `"source":"local"` с причиной перехода.

Для проверки ответов служит отдельный промпт `REVIEW_INSTRUCTIONS`. Вход — исходное описание, тема, текущие поля без контактного и массив `answers` вида `{"field":"need","question":"Что нужно изменить?","answer":"Сократить ожидание"}`. Модель возвращает структурированный JSON `{"items":[{"field":"need","ok":true,"feedback":""}]}`; для ответа не по теме — `ok=false` и конкретное объяснение. Сервер требует ровно по одному валидному вердикту на каждое поле. `POST /api/tasks/{id}/review` возвращает `source`, `issues` и `checked`, не сохраняя ответы. `POST /api/tasks/{id}/confirm` повторяет проверку на сервере; при проблемах возвращает HTTP 422 с `issues`, не меняя опубликованную версию. Пустые поля разрешены, поэтому низкорейтинговые задачи остаются возможными. Контактное поле проверяется только локально и не включается в отправляемый модели JSON.

Учитывайте конфиденциальность: не отправляйте в AI личные или чувствительные данные в черновике. AI не проверяет правдивость фактов, не переписывает ответы и не публикует их сам. При недоступности API приложение честно сообщает о локальном режиме: он отсеивает очевидные заглушки, но не гарантирует смысловую проверку.

## Архитектура

`app.py` — HTTP API и SQLite; при запуске старые демо-базы дополняются новыми полями без удаления записей. Для подтверждённой задачи хранятся версия редактора и последняя опубликованная версия. `static/index.html` и `static/app.js` — пять разделов интерфейса; `static/*.css` — адаптивное оформление со светлой и тёмной темой. Секреты и данные не хранятся в репозитории. `python3 -m unittest -v test_app.py` проверяет сквозной сценарий.

## Ограничения прототипа

Без API-ключа уточняющие вопросы выбираются из локального набора правил, а проверка ответов ограничена очевидными заглушками. Даже при подключённом AI вердикт о релевантности может ошибаться и не доказывает правдивость сведений; бизнес может исправить ответ или оставить поле пустым. Для реального запуска также нужны авторизация, права доступа, защита от спама и полноценный хостинг.
